# Offer 罗盘竞品分析教师汇报版

## 一句话结论

Offer 罗盘不应该做成“又一个 AI 简历工具”，而应该做成**大学生求职过程管理与 AI 辅导系统**。

我们不和超级简历比模板，不和牛客比题库，不和实习僧/BOSS/智联比岗位数量，也不照抄求职方舟的自动填表插件。我们的机会是把这些竞品割裂的能力串成一条学生真正能执行的求职闭环。

> 外部岗位/JD -> 简历匹配分析 -> 投递准备度判断 -> 改写建议 -> 保存简历版本 -> 加入投递进展 -> JD 模拟面试 -> 面试复盘 -> 用户画像

---

## 1. 竞品分析后，我们发现用户真正喜欢什么

| 用户喜欢的功能 | 代表竞品 | 用户为什么喜欢 | Offer 罗盘应该怎么做 |
|---|---|---|---|
| 针对 JD 改简历 | 求职方舟、超级简历 | 直接影响投递结果，比泛泛润色更有用 | 把简历分析固定成“岗位要求、匹配证据、能力缺口、改写建议、投递准备度” |
| 投递进展表 | 求职方舟、Excel/飞书表格 | 海投后最容易乱，记录能降低焦虑 | 投递表必须和 JD、简历版本、面试复盘绑定，不能只是普通表格 |
| 岗位汇总表 | 求职方舟、实习僧、牛客 | 信息集中，节省到处找岗位的时间 | 先做精选岗位，不做全网爬虫；每条岗位标来源、更新时间、截止状态 |
| 模拟面试 | 牛客 | 面试前需要练习，能缓解焦虑 | 面试问题必须来自目标 JD 和用户简历，不能问泛泛问题 |
| 简历基础纠错 | 超级简历 | 新手容易犯格式、措辞、量化表达错误 | 作为辅助体检功能加入，不取代 JD 匹配分析 |
| 报告导出 | 超级简历、各类简历工具 | 用户需要一个可交付、可复盘的结果 | 后续导出简历分析报告和面试复盘报告 |

## 2. 竞品里用户容易吐槽什么，我们必须避开

| 容易被吐槽的功能 | 问题在哪里 | 我们的规避策略 |
|---|---|---|
| 自动填表插件 | 安装麻烦、兼容失败、企业官网表单差异大 | 暂不做插件，先做投递材料清单和可复制字段 |
| 自动投递 | 容易误投，也可能触碰平台规则和合规边界 | 不做全自动投递，只做投递提醒、官网跳转、进度记录 |
| 海量岗位爬取 | 岗位过期、重复、来源不清会严重伤害信任 | 宁可岗位少，也要来源清楚、状态清楚、更新时间清楚 |
| 直接代写简历 | 内容同质化，也可能让学生失去真实表达 | 给改写建议和原因，不直接替学生生成最终版 |
| 突然收费 | 学生对导出、保存时才提示付费很敏感 | 会员权益提前说明，先用内测额度和兑换码验证 |
| 笔试实时辅助 | 容易触碰作弊边界 | 只做模拟训练和复盘，不做考试辅助工具 |

## 3. 重点竞品对我们的启发

### 3.1 求职方舟 AI

它最值得学的是“工具集合”和“求职闭环”：AI 改简历、AI 找工作、岗位表、内推表、投递进展表、会员体系都串在一起。

但我们不能照抄自动填表和自动投递。这个功能看起来强，但技术兼容、平台规则、用户信任风险都高。Offer 罗盘现阶段更适合做“辅导型产品”，不是“替代型产品”。

**我们学它：**岗位表、投递表、AI 简历分析、会员权益分层。  
**我们避开：**浏览器插件、自动投递、过早支付。

### 3.2 超级简历

它最强的是简历成品感：模板多、导出方便、AI 优化措辞、基础纠错明确。

但它更像简历编辑器。Offer 罗盘不应该被带偏去做模板市场。我们的关键不是“简历好不好看”，而是“这份简历适不适合这个岗位”。

**我们学它：**简历表达专业度、基础纠错、结果有成品感。  
**我们避开：**模板堆叠、只做通用润色、收费点不透明。

### 3.3 牛客

它最强的是题库、面经和模拟面试。用户喜欢它，是因为能看到真实题、真实面经、真实求职经验。

但牛客内容太重，短期无法复制。Offer 罗盘应该做更轻、更个人化的面试训练：根据用户自己的简历和目标 JD 生成问题。

**我们学它：**面试训练、岗位准备、真实感。  
**我们避开：**大而全题库、开放社区、笔试作弊边界。

### 3.4 实习僧、智联、BOSS、猎聘

这些平台强在岗位供给，不是强在个人求职辅导。用户去那里找岗位，但仍然不知道自己适不适合、怎么改简历、怎么准备面试、怎么复盘失败。

所以它们不是我们要正面打的对手，而是我们的上游岗位来源。

**我们学它：**岗位分类、岗位状态、外部链接。  
**我们避开：**和大平台比岗位数量。

## 4. Offer 罗盘下一步就做这几件事

| 优先级 | 要做什么 | 为什么必须做 | 验收标准 |
|---|---|---|---|
| P0 | 重构简历分析结果 | 现在用户最需要知道“这份简历能不能投这个岗位” | 结果页先显示投递准备度，再显示证据和建议 |
| P0 | 保存简历版本 | 不同 JD 需要不同简历 | 每次分析能保存为一个岗位版本 |
| P0 | 投递进展表持久化 | 求职是长期过程，本地记录不够 | 关闭页面后投递记录不丢失 |
| P0 | 模拟面试绑定 JD | 面试训练必须和目标岗位相关 | 每道题能对应 JD 要求或简历经历 |
| P1 | 岗位列表增加来源和状态 | 岗位信息最怕不可信 | 显示来源、更新时间、截止日期、是否过期 |
| P1 | 个人页做求职画像 | 把使用记录变成复盘价值 | 展示投递数、面试数、薄弱能力、下一步建议 |
| P2 | 会员权益草案 | 商业化可以设计，但不能抢在验证前 | 先做权益展示和内测额度，不急着真实支付 |

## 5. 给老师的最终判断

这个项目值得继续做，但不能继续往“功能堆砌”方向走。

竞品已经证明：大学生愿意使用 AI 简历优化、岗位汇总、模拟面试、投递进展表这些工具。问题是市面产品大多是单点工具，或者功能集合但路径不够清晰。

Offer 罗盘的价值不在于发明一个全新功能，而在于把学生求职过程做成一个清晰闭环：

1. 用户拿到一个具体岗位 JD；
2. 系统判断简历和岗位是否匹配；
3. 系统告诉用户先改哪里、为什么改；
4. 用户保存这一版简历并加入投递；
5. 面试前按这个岗位训练；
6. 面试后复盘并反哺下一版简历。

只要这条路径跑通，Offer 罗盘就不是“AI 简历 Demo”，而是一个可以在校园就业指导场景中持续使用的求职辅导产品。
