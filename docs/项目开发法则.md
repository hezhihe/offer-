本文件是 Offer 罗盘后续开发的最高优先级项目规则，来源于两份主导文档：

1. `docs/竞品分析教师汇报版_v2.pdf` / `docs/竞品分析教师汇报版_v2.md`
2. `C:\Users\LEGION\Desktop\ai编程学习\《从_Demo_到真实上线：AI_编程到底怎么学》.pdf`

后续所有开发、线程分配、代码修改、验收，都必须先对照本文件。不能再脱离主线做局部无用优化。

---

## 一、产品总方向

Offer 罗盘不做“又一个 AI 简历工具”，而要做：

> 大学生求职过程管理与 AI 辅导系统

核心价值不是帮用户生成一份漂亮简历，而是把学生求职过程中割裂的环节串起来：岗位、JD、简历、投递、面试、复盘、个人画像。

---

## 二、唯一主工作流

所有功能都必须服务这条路径：

```text
外部岗位/JD
-> 简历匹配分析
-> 投递准备度判断
-> 改写建议
-> 保存简历版本
-> 加入投递进展
-> JD 模拟面试
-> 面试复盘
-> 用户画像
-> 反哺下一版简历和下一次投递
```

如果一个改动不能让用户更顺利走完这条路径，默认不做，除非它是阻塞 bug、安全问题或上线必需工程问题。

---

## 三、P0 / P1 / P2 开发优先级

### P0：必须先跑通的核心闭环

1. 简历分析结果必须围绕具体 JD：
   - 岗位要求
   - 匹配证据
   - 能力缺口
   - 改写建议
   - 投递准备度

2. 每次 JD 分析必须能保存为一个岗位简历版本。

3. 投递进展表必须持久化，关闭页面后记录不丢。

4. 模拟面试必须绑定具体 JD 和用户简历，不能只是泛泛题目。

5. 面试结束后必须形成复盘：
   - 命中点
   - 最大问题
   - 能力短板
   - 可补进简历的表达
   - 下一步行动

### P1：增强复盘和可信度

1. 岗位列表显示来源、更新时间、截止日期、状态。
2. 个人页形成求职画像：投递数、面试数、薄弱能力、下一步建议。
3. 投递表绑定 JD、简历版本、面试记录，形成复盘链路。

### P2：商业化和扩展

1. 会员权益草案可以展示，但不急着接支付。
2. 不急着做自动填表、自动投递、大而全题库、社区、完整爬虫系统。
3. 收费权益要提前说明，不能突然卡住核心流程。

## 四、竞品启发与边界

### 要学习

- 求职方舟：把简历、岗位、投递串起来。
- 超级简历：建议要具体、清楚、有交付感。
- 牛客：面试训练要真实、有针对性。
- 实习僧、智联、BOSS、猎聘：岗位要有来源、状态、外链、截止信息。

### 不要走偏

- 不做模板市场。
- 不和招聘平台比岗位数量。
- 不做大而全题库和社区。
- 不过早做自动投递、自动填表、复杂会员支付。
- 不直接代写、代投；产品定位是辅导和训练，不是替学生完成求职。

## 五、AI 编程开发方法

本项目必须按“从 Demo 到真实上线”的方法推进。

### 1. Demo 验证版

目标是快速验证：

- 项目给谁用。
- 用户看不看得懂。
- 核心流程能不能跑。
- 页面有没有感觉。
- 方向值不值得继续做。

Demo 可以快，但不能乱。至少要有清楚页面、核心流程、假数据、可演示结果。

### 2. MVP 真数据版

目标是从“能看”进入“能用”。

最小真实数据闭环是：

```text
用户提交数据
-> 数据保存到数据库或本地持久层
-> 后台/页面能读取
-> 用户能看到结果
```

本项目优先使用现有 FastAPI、Supabase、localStorage/sessionStorage 跑通闭环，不为炫技引入复杂架构。

### 3. 上线工程版

在继续加功能前，必须把项目收干净：

1. 重新确认用户主流程。
2. 重新整理页面和功能。
3. 明确页面、组件、接口、store、数据库的边界。
4. 补最小验收检查：
   - 正常流程能跑通。
   - 错误输入能拦住。
   - 数据真的保存。
   - 新功能不破坏旧功能。
   - 出错能看到原因。
   - README 或文档写清楚启动方式。

### 4. 隔离迭代版

新功能不能直接乱塞进主流程。正确顺序是：

```text
单独做
-> 假数据验证
-> 接真实数据
-> 确认稳定
-> 接入主流程
-> 回归测试
```

## 六、线程和任务分配规则

1. 总控线程负责方向、边界、验收，不直接同时派发过多任务。
2. 默认一次只激活 1 个开发线程，最多额外 1 个文档线程。
3. 给线程分配任务时，必须先用产品语言说明用户路径，再写技术文件边界。
4. 线程只改自己模块相关文件，不跨模块乱改。
5. 线程完成后，总控必须做独立验收：源码关键点检查、构建检查、预览检查。
6. 对安全的读取、搜索、构建、普通功能文件写入，可以自动推进；删除、重置、密钥、系统配置、AiMaMi 代理配置必须停下。

---

## 七、每次开发前必须回答的问题

每个功能开工前，必须先判断：

1. 它属于主工作流哪一步？
2. 它解决哪个用户痛点？
3. 它是 P0、P1 还是 P2？
4. 有没有更小的实现方式？
5. 会不会破坏已有核心流程？
6. 如何验收？

答不上来，就不要开工。

---

## 八、每次项目回答固定结构

项目相关回复必须包含：

1. 错误根源：本质问题是什么。
2. 涉及技术栈：具体涉及 Vue、Pinia、FastAPI、Supabase、JWT、File API、FormData、CSS、部署、数据库或 API 代理等。
3. 为什么这样做：说明取舍，不只说改了什么。
4. 对应功能是什么：映射回用户路径。

最后一行固定：

```text
Frontend preview URL: <url>
```

没有预览地址则写：

```text
Frontend preview URL: unavailable
```

## 九、当前最重要的开发方向

接下来不要继续散改按钮和局部页面。优先推进：

```text
JD 模拟面试
-> 面试复盘
-> 识别能力短板
-> 写入用户画像
-> 反哺简历改写建议
```

这是从“单点 AI 工具”升级成“求职过程辅导系统”的关键。
